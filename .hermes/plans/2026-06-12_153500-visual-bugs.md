# FreqUI — Bugs Visuales

> **For Hermes:** Plan mode. Visual/layout bugs found across the project.

**Goal:** Fix all visual bugs caused by incorrect CSS classes, leftover debug code, and layout issues.

**Root Cause:** The project uses **Tailwind CSS v4** but has many **PrimeFlex** CSS class names (from PrimeFlex/PrimeFaces) that don't exist in Tailwind. PrimeFlex is NOT installed as a dependency. These classes are silently ignored, causing layout breaks.

---

## B1 — PrimeFlex classes que no funcionan sin PrimeFlex

El proyecto usa Tailwind CSS pero tiene ~30 clases de **PrimeFlex** que no existen en Tailwind. Como PrimeFlex no está instalado, estas clases no aplican ningún estilo, causando bugs de layout.

## B4 — NavBar mobile menu: Drawer sin botón de cierre funcional en algunos casos

**File:** `src/components/layout/NavBar.vue:353-413`

El drawer mobile tiene un botón de cierre (i-mdi-close) pero no usa el mecanismo de `visible` del Drawer de PrimeVue. El `v-model:visible` maneja la apertura/cierre, pero el botón manual podría solaparse con el comportamiento del Drawer.

**Fix:** No crítico, pero verificar que el botón de cierre funciona correctamente.

## B5 — NavBar botón "Lock dynamic Layout" checkbox no sincronizado

**File:** `src/components/layout/NavBar.vue:147-151`

```html
<BaseCheckbox v-if="item.checkbox" v-model="item.checked" />
```

El `item.checked` es reactivo pero es un `ref` dentro del array `menuItems`. El valor `checked: layoutStore.layoutLocked` se evalúa una sola vez al crear `menuItems`, no se mantiene sincronizado.

**Fix:** Usar una referencia reactiva al store:
```ts
checked: computed(() => layoutStore.layoutLocked),
```

---

## B6 — TradingViewCandleChart: position: absolute sin z-index stacking explícito

**File:** `src/components/charts/TradingViewCandleChart.vue:712-719, 800-812`

Los elementos `.ft-tradingview-crosshair` e `.ft-tradingview-indicators` usan `position: absolute` con `z-index: 3` y `z-index: 2`. La primitiva personalizada (Canvas) se renderiza por encima con `zOrder: 'top'`. Esto puede causar que los labels del crosshair queden debajo de los markers dibujados por la primitiva.

**Fix:** Verificar que el z-index del crosshair (3) esté por encima de la capa de la primitiva.
